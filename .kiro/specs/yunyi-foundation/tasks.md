# 实施任务：状态与持久化基础

完整串行任务清单；独立任务图审查通过，用户批准待定。所有行为任务均使用测试作者 → 真实 RED → 代码作者 → 不变测试 GREEN → 三项独立审查；不复用 spike 实现。需求编号只在本规格内解释。

- [ ] 1. 可复现基础
- [ ] 1.1 建立可安装包和严格测试门禁（约2小时）
  - 使用已验 conda 解释器，锁定直接依赖与开发依赖，声明 pywin32 为 Windows 直接依赖。
  - 实际测试缺少运行器、零测试、收集错误、假 RED 和测试篡改均被拒绝。
  - 完成时可构建 wheel，测试入口、原始验证器和加严门禁均能运行；审查状态缺失不能标完成。
  - _Boundary: PackageSetup, TDDGate_
  - _Requirements: 1.2, 6.1_
- [ ] 1.2 实现配置覆盖、校验及工作区解析（约1小时）
  - 固定四层优先级与默认值，非法参数在 IO/执行前失败。
  - 覆盖未知字段、相对路径、空目标、非正阈值和不支持并发。
  - 完成时测试能观测配置来源，环境秘密不出现在展示中。
  - _Boundary: Config_
  - _Requirements: 1.1, 1.2, 1.4_
- [ ] 1.3 实现严格计划、任务、结果及凭证模型（约2小时）
  - 使用判别动作模型和有限大小约束，测试环、自依赖、缺失依赖和旧字符串命令。
  - 冻结序列化、规范 hash、枚举及 schema_version，供下游消费。
  - 完成时有效计划序列化往返一致，非法计划返回准确字段错误。
  - _Boundary: Models_
  - _Requirements: 4.1, 4.4_

- [ ] 2. 可解释网络状态
- [ ] 2.1 实现四态与独立计数（约2小时）
  - 每条转移先写测试，覆盖首次失败、第三次失败、恢复首成功和再次失败。
  - 加入高延迟降级与主服务判定，失败/健康成功计数不能互相混淆。
  - 完成时给定采样序列得到逐轮确定状态，取消不产生样本。
  - _Depends: 1.3_
  - _Boundary: StateMachine_
  - _Requirements: 2.2, 2.3, 2.4, 2.5, 2.6_
- [ ] 2.2 实现有界多目标探测（约2小时）
  - 使用真实本地 HTTP 和不可达端口验证响应、超时、认证响应及错误分类。
  - 验证主目标失败时备用成功不能造成稳定状态，轮次不重叠。
  - 完成时每轮返回目标耗时和分类，停止后不留探测任务。
  - _Depends: 1.2, 2.1_
  - _Boundary: NetworkMonitor_
  - _Requirements: 2.1, 2.5_
- [ ] 2.3 实现滑窗估计、陈旧检测和稳定等待（约2小时）
  - 使用注入单调时钟验证窗口裁剪、少样本、零成功与时间跳变。
  - 等待真实稳定持续时长，支持超时和取消，不使用预测值替代。
  - 完成时边界指标均在定义范围内，陈旧快照不会许可规划。
  - _Boundary: NetworkMonitor_
  - _Requirements: 3.1, 3.2, 3.3_

- [ ] 3. 事务账本
- [ ] 3.1 建立完整 schema 与事务迁移（约2小时）
  - 创建设计中的全部表、复合外键和索引，启用 DELETE/FULL 与有界 busy。
  - 测试未知未来版本、迁移中断、外键越界及 WAL 不兼容拒绝。
  - 完成时新库可重复打开，失败迁移不留半套 schema，integrity_check 正常。
  - _Depends: 1.3_
  - _Boundary: Repository_
  - _Requirements: 4.3, 5.4, 5.5_
- [ ] 3.2 实现会话、计划与幂等入队（约2小时）
  - 会话绑定工作区，计划与任务整体提交，审批和保存分离。
  - 测试相同 hash 重复提交、不同内容冲突和不同会话同名任务。
  - 完成时失败计划不留任何任务残片，未批准任务不会进入可执行队列。
  - _Boundary: Repository_
  - _Requirements: 1.3, 4.1, 4.2, 4.3, 4.4_
- [ ] 3.3 实现原子领取、前后检查点及终态提交（约3小时）
  - 两个真实进程竞争一次领取，终态提交比较 attempt/version。
  - 结果、后检查点和状态原子提交，旧令牌必须失败。
  - 完成时一个步骤只有一个有效执行者，落库错误不显示虚假成功。
  - _Boundary: Repository_
  - _Requirements: 5.1, 5.2, 5.5_
- [ ] 3.4 实现孤儿事实标记、事件和报告查询（约2小时）
  - 持久化所有者身份与 generation，验证死亡后才把 running 转需核对。
  - 查询保持会话隔离，不返回执行令牌，事件可按序号补读。
  - 完成时模拟写副作用后崩溃仍保留未知事实，不自动重复排队。
  - _Boundary: Repository_
  - _Requirements: 4.3, 5.3, 6.1_
- [ ] 3.5 实现多步骤回滚父子账本与领取提交接口（约2小时）
  - 回滚父操作冻结逆序子清单，start/end与子状态在短事务内提交。
  - 测试重复operation内容冲突、旧lease拒绝、applied不重复领取和孤儿running进入需核对。
  - 完成时多步回滚进度可在重启后逐项辨认，外部服务不直接改表。
  - _Boundary: Repository_
  - _Requirements: 5.1, 5.2, 5.3, 6.1_

- [ ] 4. 可观测基础与集成验证
- [ ] 4.1 实现安全日志、输出摘要和真实指标（约2小时）
  - 用含伪造密钥、认证头、长输出的测试验证脱敏与限长。
  - 只统计实际事件，无样本指标为空，日志轮换不丢账本事实。
  - 完成时 JSONL 可解析且没有测试秘密明文，指标分母可追踪。
  - _Depends: 3.4_
  - _Boundary: AuditLog_
  - _Requirements: 6.1, 6.2, 6.3_
- [ ] 4.2 完成基础跨模块契约验收（约2小时）
  - 连接真实探针、状态机和临时数据库，验证事件、快照与重启查询。
  - 执行完整 foundation 测试、wheel 构建与导入，交付下游接口清单。
  - 完成时全套证据新鲜且独立审查通过；此处不标记产品最小闭环已通过。
  - _Depends: 2.3, 3.5, 4.1_
  - _Boundary: FoundationIntegration_
  - _Requirements: 2.1, 3.3, 5.3, 5.5, 6.1_
